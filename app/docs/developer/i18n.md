# Internationalization

ModelRails ships in English only, but everything user-facing goes through I18n
anyway. That is not aspirational multi-language support — it is what lets a fork
rewrite every string in the product without touching a template, and it is why
the design-system rule "no hardcoded UI strings" is enforceable at all.

Two gates keep it honest. Both fail the suite, so neither can rot.

## Where keys live

Content lives in domain-split files under `config/locales/en/`:

```
config/locales/
  en.yml                    # catch-all — see below
  en/
    auth.en.yml
    workspaces.en.yml
    notifications.en.yml
    …
```

Rails loads `config/locales/**/*.{rb,yml}`, so **any** `.yml` in that tree is
picked up — with or without the `.en.` infix. Prefer the infix for consistency
with the existing files.

`config/locales/en.yml` holds no keys. It is the landing zone for
`i18n-tasks add-missing`; anything that appears there still needs a home in a
domain file.

## The two gates

### `raise_on_missing_translations` (runtime, test only)

Enabled in `config/environments/test.rb`. A `t()` call for a key that does not
exist raises instead of rendering `translation missing`. It catches real
regressions, but only on code paths a spec actually walks — and only when the
call site has no inline `default:`.

It is deliberately **off in development**, where a missing key renders inline.
That is the more useful signal while a page is still being built, and the
Lefthook pre-push hook runs the suite, so a missing key cannot reach a PR.

### `i18n-tasks` (static, `spec/i18n_spec.rb`)

Scans the repo without executing anything, so it sees paths no spec covers —
including call sites with an inline `default:` masking the gap.

```bash
bundle exec i18n-tasks missing        # gated — fails the suite
bundle exec i18n-tasks check-consistent-interpolations   # gated
bundle exec i18n-tasks unused         # not gated yet
bundle exec i18n-tasks normalize      # not gated yet
```

It runs as an ordinary spec rather than a separate CI step, so CI and the
pre-push hook get it with nothing to keep in sync.

**When the gate fails, add the key.** Do not add an entry to `ignore_missing` or
disable the config — those exist for engine-owned namespaces, not for
convenience.

## Lazy keys: only inside actions

Rails resolves `t(".key")` in a controller against `action_name`. Inside a
**private helper**, that scope is a claim the code cannot honour — and static
analysis, which resolves the enclosing *method* name, cannot verify it either.

This bit us: `invalid_token` and `expired_or_used` were defined only under
`create:`, while the shared `find_valid_invitation` filter also ran for `show`.
Both flashes rendered `translation missing` to real users, and the request specs
passed because they asserted only the redirect.

The rule:

```ruby
def show
  redirect_to root_path, alert: t(".not_found")           # ✅ inside an action
end

private

def find_valid_invitation
  redirect_to root_path, alert: t("invitations.invalid")  # ✅ absolute
end
```

And assert the **message**, not just the redirect:

```ruby
expect(response).to redirect_to(root_path)
expect(flash[:alert]).to eq(I18n.t("invitations.invalid"))
```

## Validation messages

Pass a symbol; put the text in a locale file. Never inline the string, and never
use `I18n.t(..., default: "…")` — the default silences the gate permanently, so
a missing key looks healthy forever.

```ruby
# ✅
errors.add(:join_policy, :personal_must_be_invite)
```

```yaml
en:
  activerecord:
    errors:
      models:
        workspace:
          attributes:
            join_policy:
              personal_must_be_invite: "must be 'invite' for personal workspaces"
```

One caveat: `activerecord.errors.*` is in `ignore_unused`, because Active Model
consumes those keys rather than any explicit `t()` call. That means a key left
behind by a deleted validation will never be reported — remove it by hand.

## Dates and times

Render dates through `I18n.localize`, never `strftime`:

```erb
<%= l Date.current, format: :long %>
```

`:default`, `:short` and `:long` come from ActiveSupport. Override them, or add
your own, in a locale file:

```yaml
en:
  date:
    formats:
      long: "%-d %B %Y"      # 25 July 2026 instead of July 25, 2026
      invoice: "%Y-%m-%d"
```

Every `l` call in the app then follows, with no template edits.

## Adding a language

**`config.i18n.available_locales` is pinned to `[:en]` in
`config/application.rb`. Register your locale there first.**

That pin is not ceremony. Without it, `available_locales` is derived from the
load path — and `faker` (a development/test gem shipping ~350 locale files) made
it ~60 entries under test and `[:en]` in production. `I18n.translate` calls
`enforce_available_locales!` *before* it reaches the backend, so an unregistered
locale raised `I18n::InvalidLocale` in production while specs passed. That
shipped a 500 on the notification bell for any user whose saved locale was not
`en`.

So:

1. Add the locale to `config.i18n.available_locales` in `config/application.rb`.
2. Add `config/locales/fr/*.fr.yml`.
3. Run `bundle exec i18n-tasks missing` — it compares every locale against
   `base_locale` and lists what you still owe.

`UserPreferences#locale` validates against `available_locales`, so a language
you have not registered cannot be selected.

### Know what the runtime gate does not cover

`config.i18n.fallbacks = true` is set in test, development and production, so a
lookup that misses in `:fr` terminates at `:en` rather than dying. That is the
right production behaviour — but it means **a missing `:fr` key resolves to
English and your `:fr` specs pass on English text.**

Cross-locale completeness is `i18n-tasks missing`'s job, not
`raise_on_missing_translations`'s. If you add a language, that static gate is
the one keeping you honest.

## Fork seams

| File | What a fork changes |
|---|---|
| `config/application.rb` | `available_locales` — register a new language |
| `config/locales/en/*.en.yml` | Product copy, per domain |
| `config/locales/en/brand.en.yml` | Product name and brand strings |
| `config/i18n-tasks.yml` | `ignore_missing` if you mount another engine |
| `config/environments/*.rb` | `raise_on_missing_translations` if you want it in development too |
